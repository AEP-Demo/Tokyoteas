Identity architecture

FPID and ECID: a visitor ID that survives browser limits.

Browsers now cap the lifetime of cookies set by JavaScript, so a returning visitor can look new after a few days. A first-party device ID (FPID), set by your own server, keeps the identity stable. The Adobe Edge Network uses it to derive the Experience Cloud ID (ECID), so Adobe reports and audiences keep recognizing the same visitor.

1 · Your server

Sets FPID

An HTTP-only, first-party cookie written by your web server or CDN.

2 · Web SDK

Sends identityMap

The FPID is passed to the Edge Network with each event.

3 · Edge Network

Derives ECID

When no ECID is present, the ECID is generated from the FPID.

4 · Activation

One visitor everywhere

Analytics, CJA, Target and Real-Time CDP read the same ID; GA4 can carry it too.

We run this on our own site

Axiometriq.com uses the same pattern: an FPID set at the edge by Cloudflare, with the ECID and every tag managed in Adobe Tags. It's how we test what we recommend.
